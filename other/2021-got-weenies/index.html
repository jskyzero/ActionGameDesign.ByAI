《对马岛之魂》的地标引导：让岛屿指引你

🗼 地标引导🌄 开放世界🌬️ 无 UI 引导
核心观点

最好的引导不是地图上的标记，而是让岛屿本身开口说话——把地标、风与动物变成世界的语言。

原标题Exploration in Ghost of Tsushima: Letting the Island Guide You
原链接 https://gdcvault.com/play/1027399/Exploration-in-Ghost-of-Tsushima
作者简介 Parker Hamilton · Sucker Punch Productions 首席游戏系统设计师，曾负责《声名狼藉》系列与《对马岛之魂》的系统设计。
其他参考 GDC Vault（原） · GameDeveloper 原文（原） · 机核听课笔记（译）

设计起点：让玩家「流浪」在封建日本

  • 关键词是流浪（wandering）——想做一款能让人在封建日本迷路、沉浸其中的开放世界：爬一座山、走向树梢间露出的寺庙、或骑马穿过森林去追一名落单的浪人。
  • 不用小地图等抽象 UI：它们不「diegetic」（不符合故事世界观），所有解决方案都必须有机且叙事化（organic and diegetic）——看起来像是世界本身的一部分。
  • 地域差异化：三大区域各有独特的色彩与地形（如 Toyotama 沼泽湿地中的疗养小镇 Akashima——巨钟与寺庙）；每个地点都要有历史感——「这里过去发生了什么？现在是什么状态？玩家到来之后又会发生什么？」

Weenie：从迪士尼借来的地标引导

  • 术语来自 Disney Imagineering：乐园里最高、最中心的建筑（城堡 / EPCOT）始终吸引游客走向它。
  • Weenie = 看得见的地标：负责导航、制造惊奇，并形成贯穿整个世界的一致规则。

Flags：向上生长的「旗标」

  • 高大地标、与天际线形成对比：狼烟、建筑、红枫树、鸟群，按各自优先级在不同距离可见。
  • Short Flag（短旗标）：只在近距离可见的高物体——作用是告诉玩家「你的直觉没错，这里确实有东西」，但远处看不到，是被审视的对象。

Breadcrumbs：地面层的「面包屑」

  • 鸟居（Torii Gate）：隐藏寺庙的入口标记，按间隔排列让玩家穿过——像通往新内容的「软倒计时」；「即使身在密林中也能被发现」。

粒子与声音

  • 烟、树叶、鸟、萤火虫等粒子能让地标远处可见、昼夜可见、靠近时变化，还能随内容完成度而改变。
  • 声音也能赋予地标身份：渐近的蒙古鼓声提示附近有营地。

30 秒规则

  • 移动中每 30 秒或更短必须能看到一个「召唤物」——不是撞到东西，而是能远远看见有东西在召唤。
  • 缩短间隔有时不是加内容，而是砍树、清灌木让地标露出来（例：小松镇被树木遮挡、本应可见的篝火烟被「纯装饰」的树挡住）。

偶遇内容（Stumble Content）

  • 定制内容（Bespoke Content）：让玩家觉得自己发现了一个隐藏地点（如秘宝）。
  • 动态内容（Dynamic Content）：路上的随机互动、小游戏、收藏、随机挑战——让世界显得更有生机。
  • 任务设计配合：任务起点与终点尽量拉开距离，让途中有机会偶遇这些内容，而不是在原地打转。

探索奖励（Reward Exploration）

  • 规则：所有地点都有奖励，范围分四类：
    • 世界的内容
    • 游戏优势（属性 / 技能 / 装备）
    • 自我表达（换装、绝佳景点）
    • 快速传送（开图）

风引导（Windicator）：把指南针藏进世界

  • 放弃 HUD：指南针、头顶 UI、地图标记承载的信息太多，破坏沉浸、让人分心；图标繁杂、笨拙、没有代入感。
  • 原型迭代：手指光束、雾化的鹿、丁达尔光束……最终选定风——设定目标后，风会吹动草木与粒子指向目标方向，目标变更时 HUD 给出即时反馈。

玩测发现的问题与改进

  • 可视性（Visibility）：骑马穿过树林、雨天时看不清风 → 大幅提高风力与粒子可视性，加呼风按钮（随时唤起一阵可见的风，白色丝线即前进方向）。
  • 向导性（Navigation）：风只指直线，但河要绕渡口、崖壁爬不上去 → 漏斗形感知地形的粒子（沿陡峭山崖上升消失）+ 补充可攀爬路径。
  • 任务整合（Mission Integration）：一次只追踪一个目标；删除自动任务（会打乱指引）；与 NPC 对话时关闭风引导（风会不断吹拂 NPC），离开后再激活；区域型任务进入区域时关闭、离开时激活。
  • 结果：UI 大幅减少、世界更美——风成为游戏「物哀」气质的一部分，过场动画也配合改得干净简洁。

动物向导：鹿、鸟、狐、萤火虫

  • 无 UI 后「未探索区域标记」失效 → 大型区域（敌营）用鲜明的视觉 / 听觉元素吸引；小型区域（神社）要花更多精力去寻找。

  • 系统化地在待探索区域附近生成动物来引导。

  • 鹿：引导主角，但爬不上悬崖。

  • 鸟：在鹿到不了的地方接力引导，像开盲盒——抵达前不知道会探索到什么；大部分情境下引导会被清除，以免分散玩家注意。

  • 鹰的转变：最初设计是帮敌人发现主角（玩家的躲避对象）→ 被改造为玩家的引导动物。

  • 狐：全部定制，有固定寻路路线，目标是营造「找到隐藏神秘地点」的感觉；路径非一本道，途中安排不难的挑战加深成就感；还设计了「跟丢狐狸再找回」的内容。

  • 萤火虫：原地盘旋，把自己置于玩家与收集品之间；靠近时荧光脉冲变得更频繁。

播种新机遇：NPC 的传闻

  • 让 NPC 有自己的故事，通过 NPC 周遭的世界构建起游戏的历史真实感。
  • NPC 动态散布在地图上，倾诉自己的遭遇、透露与探索相关的信息（传闻）。
  • 直觉式的参数管理：提示村民的密度、村民之间的间隔、冷却时间、提示上限（按内容种类分，每种最多 2 条）。

✦ 一句话总结：先确立「流浪」的美学目标，再用地标（weenie）、风与动物替代 UI 引导玩家——让岛屿本身成为地图，而不是给玩家一张地图。
