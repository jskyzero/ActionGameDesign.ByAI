# 内容提取与沉淀规范

本文定义「动作游戏设计知识库 · AI 驱动」中，AI 从一篇分享/文章（URL 或关键词）提取并沉淀知识的**统一逻辑**。目标是让内容可读性高、可检索、可复用。

## 收录范围

本博客主要收录与**动作设计直接相关**的内容，如战斗机制、角色操作、攻击动画、战斗 AI、战斗镜头，以及影响战斗判断的特效与可读性设计。

按分享的具体内容判断相关性，不能仅因其来自某款动作游戏就收录。通用持续集成、质量保障、制作管理，以及未涉及动作设计的背景美术等过泛主题不收录。美术或技术分享需说明其如何直接影响动作体验、战斗决策或操作反馈。

## 1. 信息密度分层（Information Density Hierarchy）

小红书内容可读性高，核心在于「字数少、视觉重点突出」。AI 总结不能只给纯文本，必须**分层提取**：

| 层级 | 内容 | 呈现 |
|---|---|---|
| **一级信息（Hook）** | 1 句抓人眼球的结论/标题 | 大字号（封面/引用块） |
| **二级信息（Core Points）** | 按材料组织的核心观点（不固定三个） | 图标 + 加粗小标题 |
| **三级信息（Details）** | 具体解释、例子、数据 | 小字号、浅色字 |

对应 schema：`article.insight`（Hook）· 正文（Details，挂在每个核心观点下）。

**提取规则**：
- Hook：只提炼**一句**，能独立成立、让人想点进去看。如果原文没有金句，用一句话概括，不要照抄整段。
- Details：还原设计问题、实现机制、具体案例、迭代与取舍。段落简短不等于全文简短，不以三个小节或固定字数截断材料。

## 2. 通用信息卡片

信息卡片要兼容不同类型的内容（不只 GDC 演讲），字段语义通用化：

| 字段 | 语义 | GDC 演讲示例 | 普通文章示例 |
|---|---|---|---|
| `article.title` | 中文标题 | 街霸 5 的美术设计思路 | 文章标题 |
| `article.insight` | 一句话结论 | 先读得懂，再求个性 | 文章主旨 |
| `article.tags` | 标签（可选 emoji 图标） | `[{label: 街霸, icon: 🥊}, …]` | `[{label: 方法论}]` |
| `source.author` | 作者 / 分享人 | 龟井敏征 · 美术总监 | 某作者 |
| `source.url` | 源链接 | GDC Vault URL | 文章 URL |
| `source.year` | 年份 | 2017 | 2024 |
| `source.type` | 会议 / 平台 | GDC | 知乎 / CEDEC |
| `source.company` | 厂商 / 来源方 | Capcom | —（可空） |
| `source.title` | 原标题 | The Art Direction of... | 文章标题 |
| `generation.model` | 生成正文的实际 AI 模型 | GPT-6 Astra | DeepSeek-V4-Pro |
| `generation.modelUrl` | 模型官方链接 | https://openai.com/ | https://www.deepseek.com/ |
| `generation.generatedAt` | 首次入库提交时间（含时区） | ISO 8601 字符串 | ISO 8601 字符串 |
| `references` | 参考（翻译/延伸） | 中译链接 | 延伸阅读 |

卡片只展示**有值的字段**；留空的字段会自动省略。

## 3. AI 提取流水线

1. **输入**：URL 或关键词。
2. **检索**：用公开信息（原视频/文章、翻译稿、官方页面）还原内容。**查找源视频时，优先找 YouTube 链接**——作者会借助 Gemini 总结视频内容并回传，便于更准确地整理正文。
3. **优先本地源**：若本地有对应 `.xmind`/`.drawio`（如 `GDC.xmind`），**以作者自己的归纳为准**，公开信息只作补充。
4. **分层提取**：按第 1 节产出 Hook + Details。
5. **归档**：生成 `.mdx`（frontmatter 结构化字段 + 正文 Details），跑 `npm run validate` 校验，再 `npm run build`。
6. **缺失补全**：标准字段（如年份、作者、源链接）缺失时，先尝试检索补全；实在找不到，用默认值占位（如年份写 `年份不详`）。

## 4. 归类

- 同一实际公司的文章达到 3 篇（`source.company`，先统一同公司别名）时，新建公司专属同级目录，并将该公司的文章统一迁入；公司目录优先于 `gdc`、`cedec`、`other`。已有厂商或专题目录保留；尚无专属目录且不满 3 篇的公司按来源放入 `gdc`、`cedec` 或 `other`。“其他”“设计者笔记”等泛分类不视为公司。目录名用 kebab-case。迁移时更新归档链接和旧 URL 跳转，历史跳转直接指向最终地址，生成时间保持不变。

- `source.company`（厂商/来源方）：沿用现有分组（Capcom / PlatinumGames / Santa Monica Studio / Nintendo / FTG 相关 / 其他 / 非 GDC / 设计者笔记），新内容按「厂商 / 品类 / 来源 / 原创」归入，必要时可新增。
- `article.tags`：推荐 2~3 个，最多 3 个，优先保留与文章核心动作设计主题直接相关的简短标签，避免卡片标签行过长。

## 5. 发布状态与生成记录

资料不足时，只在 [scan-todo.md](scan-todo.md) 保留讲题、来源与资料缺口，不发布 `wip` 占位文章。完成正文后以 `done` 收录并更新归档。

每篇文章必填 `generation`，记录实际生成正文的模型、官方链接与时间；检索所用模型不替代正文模型。既有文章的 `generatedAt` 从 `git log --follow --diff-filter=A --format=%cI -- <文章路径>` 最早的首次收录提交回填，保留时区。页面在正文末尾以右对齐斜体显示「本文由 [模型](官方链接) 于 YYYY/MM/DD 生成」，日期按北京时间换算。记录依据为首次收录提交，并非精确的模型执行时间。新增文章可预定首次提交时间，并设置相同的 `GIT_COMMITTER_DATE`；日常修改不重置生成记录。

2026-09-20 的迁移中，19 篇由 GPT-6 Astra 生成的文章按实际模型标注，其余 51 篇历史文章按用户指定统一标注 [DeepSeek-V4-Pro](https://www.deepseek.com/)。这不是未来文章的默认署名。

## 6. 从既有详实文章沉淀的复修标准

### 参考样板与值得保留的做法

- `santa-monica/2019-gow-combat`：按追踪、锁定、攻击组织依赖；保留旧站位方案失败、象限系统、吸附和 token 回收规则，能还原设计决策。
- `sucker-punch/2021-got-melee`：从目标走向测试发现，再说明强攻击、苦无和架势的具体修改；说明第一次教学如何兑现收益。
- `platinumgames/2018-nier-automata`：把输入响应、取消例外、转向窗口与逐帧调优分开，具体条件支撑抽象的「手感」。
- `capcom/2017-street-fighter-5`：篇幅短也保留角色朝向、投影调整和笔触分配等可操作细节。详实程度看证据与机制，不看篇幅。

学习其组织方式，不把既有文章当作事实来源；其中的数字、引语和实现仍需返回原材料核对。

### 先读材料，再决定章节

1. 优先完整讲义、作者文章、录像字幕；会议简介只能核实主题与讲者，不能支撑实现细节。报道需明确标识，引用其中开发者发言时保留其上下文。
2. 建立材料清单：来源、可读范围、对应章节、页码或视频时间点、未解决问题。先扫描全篇，不能只读摘要或搜索片段就生成全文。
3. 每个主要机制尽量回答：面对什么问题；旧方法为何不够；新规则怎样运行；具体角色或关卡怎样体现；解决什么又牺牲什么。材料没有的环节不补造。
4. 保留失败原型、触发条件、优先级、数值的适用范围与版本差异。用中文解释术语第一次出现的含义，不只罗列英文名称。
5. 区分讲者结论、报道转述与本文推论；后者明确标为「设计启发」或「本文归纳」。原型、未发布方案、后续研究不能写成成品实现。
6. 主体依照问题的依赖顺序展开；单段宜短，完整案例可用多个段落。拒绝把长讲义压成三个泛泛观点，也不通过重复 Hook、套话或无证据建议凑篇幅。

### 图像阅读与配图

- PDF 的文字抽取会遗漏图中对比、布局、曲线和截图里的提示；涉及这些信息时，必须查看原页图像，并记录具体页码。
- 配图承担解释任务：展示前后变化、空间关系、动作阶段或系统流程。优先少量必要的原始材料图，注明作者、来源页与图意；不转载整套讲义。
- 自制示意图明确标注「本文示意」，不得伪装成开发者原图或引擎数据。涉及真实游戏画面不使用 AI 生成图充当证据。
- Markdown 图片必须有说明性替代文本，正文独立解释关键信息，保证脱离图片仍可阅读。使用本地资源并验证构建后的路径。

### 复修验收

- 与旧稿对照，指出新补了哪些机制、案例或纠错；只有换措辞、增加小标题不算深度复修。
- 对照原材料的主要设计段落检查覆盖；节选说明范围，未获取内容登记到 `scan-todo.md`，不声称看过完整录像。
- 保留首次入库时间及真实模型署名；每篇独立运行 validate 与 build 后提交。推送依照用户授权执行。
